# Developer Guide — LeanIX vs VantageMap

**Scope note.** The SAP LeanIX *Developer Guide* (415 pages) is the complete developer/integration reference for the platform. It covers: authentication (OAuth 2.0 client-credentials via technical users), the Base URL scheme, the API suite overview (REST, GraphQL, Integration API), ~25 individual REST APIs (Pathfinder, MTM, Survey/Poll, Metrics, To-do, Webhooks, Bookmarks, Navigation/Collections, Notifications, Transformations, Import/Export/OData, Recon, Reference Data, Storage, Synclog, Discovery, plus connector APIs), the GraphQL API in depth (queries, mutations, patches, filtering/facets, cursor pagination, error handling, REST→GraphQL migration, sample queries), Webhooks (PUSH/PULL, events, payloads, callbacks, authorization), the Reporting Library + Custom Report Tools SDK (`@leanix/reporting`, `lx` API, Chart.js reports, extension hub publishing), code-based automations (webhook + FaaS tutorials), the Integration API / LDIF / data processors, rate limiting, and HTTP status codes. The MCP Server is listed in the TOC (page 2) but has no body content in this extract; it maps to PLANV4 15.3 regardless.

Most of this document is *how-to* built on a handful of underlying capabilities. The gap analysis below assesses those capabilities. Connector/Integration-API/discovery items are marked DEFERRED (PLANV4 15.6); the MCP server is DEFERRED (15.3). Core API parity (REST envelope, GraphQL, webhooks, OpenAPI, import/export, auth/tokens) is assessed against the code.

## Key gaps

Focusing on **core EA-tool API parity** (excluding the DEFERRED connector/automation/MCP items):

- **GraphQL mutations (item 6, L).** LeanIX's GraphQL is a full read+write surface (`createFactSheet`/`updateFactSheet` with JSON-patch, `createComment`, relation patches, batched aliases, transactional all-or-nothing). VantageMap's GraphQL is **query-only**; every documented mutation tutorial and the REST→GraphQL migration guide have no equivalent. This is the single largest developer-API divergence.
- **GraphQL facet filtering + cursor pagination (items 7–8).** The whole "Filtering in GraphQL" chapter (facetFilters, `filterOptions`, AND/OR/NOR, date ranges, `lxState`/`DataQuality`) is unavailable through VantageMap's GraphQL; faceting lives only in REST search. Pagination is offset-based, not relay cursors.
- **Custom Reports SDK / Reporting Library (item 26, L).** A major LeanIX developer pillar — the embeddable `@leanix/reporting` `lx` API, scaffolding CLI, Chart.js report templates, in-workspace upload, and extension hub — has no VantageMap counterpart. Reports are a fixed built-in set. Overlaps the known configurable-report-builder gap.
- **PULL webhooks + callback/auth (items 13, 15–16).** Only PUSH is implemented. No polling/cursor PULL model, no per-webhook target authorization (Basic/OAuth2), no JS payload-transformation callback.
- **Webhook event breadth (item 17, S).** Missing common events: comments, subscriptions, resources/documents, surveys, to-dos, viewed/recovered — and events are per-concrete-entity rather than a generic fact-sheet event model.
- **API rate limiting (item 32, M).** No 429/`Retry-After`/per-user quota on the API surface.
- **Async workspace snapshot export + OData (item 19).** CSV/Excel present, but no full-snapshot async export job with download key, and no OData feed.
- Smaller: OAuth2 client-credentials token exchange (item 1), Metrics ingestion API (20), Survey-run lifecycle & result retrieval (21), Bookmarks/Collections for reports & diagrams (25, 31).

## Equivalence summary

For the **plumbing** developers touch first — auth/technical users, the REST resource API (envelope, pagination, filter/sort), OpenAPI docs, import/export, webhooks, and user/permission management — VantageMap is broadly **at parity** with LeanIX. The divergence concentrates in two areas: (1) VantageMap's **GraphQL is read-only**, whereas LeanIX centers its entire fact-sheet write model, filtering, and cursor pagination on GraphQL, so mutations, facetFilters, and the REST→GraphQL migration path are all missing; and (2) there is **no Custom Reports SDK / Reporting Library** (embeddable `lx` API, scaffolding CLI, extension hub). Webhooks are functionally close (PUSH + HMAC + retry) but lack PULL, callbacks, per-target auth, and a fair slice of the event catalog. Excluding the correctly-deferred connector/Integration-API/automation/MCP mass (which is roughly a third of the document by page count), VantageMap covers most core developer-API surface, with GraphQL write-parity and the reporting SDK being the two substantial, effort-L gaps.
