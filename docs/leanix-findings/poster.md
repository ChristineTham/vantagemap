# EA Roadmap Poster — LeanIX vs VantageMap

## Scope note

`poster.txt` is a single-page (1 page of extracted text) SAP LeanIX marketing poster titled *"Your road map to a successful enterprise architecture practice."* It is not a feature spec — it depicts a high-level 4-step EA-practice lifecycle (goals → capability map → application inventory → data quality), name-checking a handful of concrete LeanIX capabilities along the way (ready-made meta model, inventory import, ownership, built-in surveys, out-of-the-box integrations, single source of truth). It also frames the "as-is architecture" starting point. I extracted each distinct capability the poster names and classified it against VantageMap. Because the doc is a poster, several "features" are really process concepts rather than tool features; I classify those as CONCEPT-level and map them to the nearest VantageMap capability.

## Key gaps

The poster's four core steps (goals, capability map, application inventory, data quality) are all covered by VantageMap at parity. The gaps are narrower and sit on the "with the right tool" claims:

- **Adaptable meta model (#6, M):** VantageMap has a strong *fixed* meta model but no way to tailor it — no admin UI for custom fact sheet types, fields, or relationship types. The poster's whole "use a ready-made meta model" pitch implies a starter you can adjust; VantageMap gives you the ready-made part only.
- **Automated survey → fact sheet loop (#8, M):** Surveys collect responses but don't run as campaigns (send/remind) and don't auto-merge findings into fact sheets, which is exactly the manual-labour-avoidance the poster sells.
- **Non-file inventory ingestion (#7, S / #9 deferred):** File import (CSV/Excel) is solid, but CMDB/BPM out-of-the-box integration — the poster's headline data-quality accelerator — is a deferred connector concern.

## Equivalence summary

For a poster that is essentially an EA-practice methodology, VantageMap is very close to LeanIX: every step it describes — setting strategy-linked goals, building a hierarchical capability map, connecting apps to capabilities, and standing up an application inventory as the single source of truth with clear ownership and as-is lifecycle state — maps directly onto shipped VantageMap features. The only real gaps are around *feeding and shaping* the model: an adaptable meta model, automated survey harvesting, and non-file (CMDB/connector) data ingestion. None of the poster's four headline steps is missing; the shortfalls are in the supporting "how you populate and customise it fast" tooling.
