# Enterprise Architecture (EA) Success Kit — LeanIX vs VantageMap

**Scope note.** This 30-page SAP LeanIX "EA Success Kit" whitepaper (2024) is a strategic/thought-leadership piece, not a feature spec. It argues *why* EA management matters (Ch.1), *how* to start an EA practice (Ch.2 — best-practice data model, choosing a tool), *how* to build the foundation (Ch.3 — capability mapping, application inventory, data quality via surveys), and *common high-value use cases* (Ch.4 — application rationalization, technology obsolescence risk, application modernization / ERP transformation). Concrete product features are named in passing rather than deep-dived; the key ones are the LeanIX meta-model (pp.8), capability maps (pp.12–13), application inventory + import (pp.14), data-quality surveys (pp.14), application portfolio report with functional/technical fit + TIME (pp.18), the Lifecycle Catalog (pp.22), custom reports + dataflow visualization (pp.22), transformation templates / target-state modelling (pp.26), and roadmaps + dependency mapping (pp.25–29). Notably, VantageMap's data model is *directly modelled on the LeanIX meta-model described on p.8* — the fact-sheet types align almost 1:1.

## Key gaps

Focusing on **core EA-tool parity** (not PLANV4/advanced):

- **Survey campaigns (#6, effort M).** VantageMap has surveys as data, but not the *operational* survey workflow LeanIX centres on for data quality — sending/scheduling to targeted app owners, reminders, and merging validated answers back into fact-sheet fields. This is a foundational LeanIX use case (Ch.3), so it's the most material core gap.
- **Configurable / custom reports + dataflow visualization (#14, effort M).** LeanIX highlights "custom reports" to surface risky apps and "visualize affected dataflows." VantageMap's reports are a fixed set and there is no visual dataflow/landscape view. The analytical substance is covered; the configurability and visualization are not.
- **Visual dependency / impact analysis (#19, effort M).** Dependency data (interfaces, relationships) is fully captured and traversable via GraphQL, but there is no *visual* dependency/impact diagram — a recurring LeanIX selling point for ERP-transformation and change-impact scenarios (pp.25, 29).
- **Capability-map visual fidelity (#3, effort S).** The hierarchical capability tree is functionally equivalent but not the intuitive coloured tile/heatmap "map" LeanIX shows on p.12; parity is close, polish is the gap.
- **Obsolescence relies on manual EOL entry (#12, effort S).** The obsolescence report and EOL fields exist; only the *automated* lifecycle-data feed (Lifecycle Catalog, #13) is absent — and that is a deferred discovery/connector concern.

## Equivalence summary

For the core EA foundation this whitepaper prescribes — a best-practice meta-model, a central repository, capability mapping, an application inventory with import, functional/technical-fit + TIME-based rationalization, obsolescence risk, roadmapping, and collaborative governance — VantageMap is a **strong, near-complete match**; its data model is essentially a direct implementation of the LeanIX meta-model on p.8, and the flagship rationalization workflow (fit scores + TIME + portfolio/coverage reports) is fully present. The gaps that remain are almost entirely about **visualization and configurability rather than missing concepts**: survey *campaigns*, custom/configurable reports, and visual dataflow/dependency/impact maps. The genuinely absent capabilities LeanIX name-drops (Lifecycle Catalog data feed, SaaS discovery, CMDB/BPM connectors, target-state transformation modelling, AI) all fall into VantageMap's explicitly deferred PLANV4 scope, so they don't count against core parity.
