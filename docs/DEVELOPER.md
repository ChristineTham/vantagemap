# Developer Guide

> Documents **VantageMap V1 (MVP)**. Reflects the actual architecture under `src/`.
> Read [AGENTS.md](../AGENTS.md) for the full conventions and stack; this guide focuses
> on how to work in the codebase.

## Tech stack (short version)

- **Next.js 16.2.6** — App Router only. No Pages Router, no `getServerSideProps`.
- **React 19.2.6** — Server Components by default; add `"use client"` only for state,
  effects, or browser APIs.
- **TypeScript 6** (strict), **Tailwind CSS v4**, **shadcn/ui** (Radix primitives),
  **Lucide** icons, **Recharts 3** (loaded via `next/dynamic`).
- **PostgreSQL 16** on **Neon** (HTTP driver), **Drizzle ORM**, **Better Auth**.

Path alias: `@/` maps to `src/`.

## API response envelope

Every API route returns a standard envelope. Helpers live in `src/lib/api-response.ts`:

- **Single item** (`ok`, `created`): `{ "data": T }`
- **List** (`list`): `{ "data": T[], "meta": { "page", "pageSize", "total", "totalPages" } }`
- **Error** (`badRequest`, `unauthorized`, `forbidden`, `notFound`, `conflict`,
  `internalError`): `{ "error": { "code", "message", "details"?, "correlationId" } }`
- **No content** (`noContent`): empty 204.

Wrap handlers in `withErrorHandler()` so thrown errors become a 500 with a correlation
id. Validate request bodies with `parseBody(request, zodSchema)` — it returns
`{ data }` or `{ error }` (a ready 400 response with per-field details).

## Authentication and RBAC in a route

Auth and permission checks are two calls at the top of every handler
(`src/lib/auth.ts` + `src/lib/rbac.ts`):

```ts
export const POST = withErrorHandler(async (req) => {
  const auth = await requireAuth(req);
  if (!auth.ok) return auth.response;            // 401

  const authz = requirePermission(auth.auth, "create");
  if (!authz.ok) return authz.response;          // 403

  // ...proceed
});
```

`requireAuth` resolves a bearer token or Better Auth session cookie (plus the
`x-dev-user-id` dev bypass) into an `AuthContext` with `userId`, `email`, `role`, and
`workspaceId`. `requirePermission` maps operations (`view`, `create`, `edit`, `delete`,
`manage_users`, `manage_workspace`, `view_audit`) to the allowed roles.

## The CRUD factory

Most entity endpoints are generated by `src/lib/crud-factory.ts`, which produces list,
get-by-id, create, update, and delete handlers for any Drizzle table that follows the
document column pattern. It handles:

- Auth + RBAC (`view`/`create`/`edit`/`delete`).
- Pagination, filtering, and sorting via `src/lib/query.ts`
  (`?page=1&pageSize=25&filter[field]=value`).
- Stripping protected fields (`qualitySeal`, `createdAt`, `updatedAt`, `createdBy`)
  from client payloads — the quality seal is governed by its own state machine.
- Audit logging via `after()` when `FEATURE_AUDIT_LOGGING` is on, including a computed
  diff for updates.

## Adding a new entity/route

1. **Schema.** Add the table to a file under `src/db/schema/` (e.g. an existing bounded
   context or a new one), reusing enums from `src/db/schema/enums.ts`. Export it from
   `src/db/schema/index.ts`. Add the type name to `documentTypeEnum` if it is a fact
   sheet.
2. **Migration.** `npm run db:generate` then `npm run db:migrate` (or `npm run db:push`
   locally).
3. **Zod schemas.** Define `create`/`update` schemas for validation.
4. **Routes.** Create `src/app/api/<resource>/route.ts` and
   `src/app/api/<resource>/[id]/route.ts` and wire them to the CRUD factory with a
   `CrudConfig` (table, `entityType`, schemas, `columnMap`). Layer any custom logic
   (hierarchies, sub-resources) on top.
5. **GraphQL (optional).** Add a type and query in `src/lib/graphql-schema.ts`.
6. **UI (optional).** Add a page under `src/app/`, following an existing `page.tsx`.
   Use `@/lib/data` for data access and Rosely colour tokens for styling.
7. **Tests.** Add Vitest tests alongside the code.
8. **Seed (optional).** Extend `src/db/seed.ts` so the entity has sample data.

## GraphQL endpoint

`POST /api/graphql` (and `GET` for introspection) is served by
`src/app/api/graphql/route.ts` using the schema in `src/lib/graphql-schema.ts`. It
requires authentication and the `FEATURE_GRAPHQL_API` flag. Types exposed include
Application, BusinessCapability, Organization, StrategicObjective, Initiative,
ITComponent, TechCategory, Provider, Platform, DataObject, and Interface (named
`InterfaceFS`). List queries support `page`/`pageSize`/`search` and return connection
objects (`nodes`, `pageInfo`, `totalCount`). Every document exposes `relatedTo` and
`relatedFrom` for relationship traversal, and queries are limited to a maximum depth of
5.

## Webhooks

The webhook engine (`src/lib/webhook-engine.ts`) delivers events to subscriber URLs
registered via `POST /api/webhooks` (managed with the `manage_workspace` permission).
Deliveries are signed with **HMAC-SHA256** (`X-Webhook-Signature: sha256=<hex>`), time
out after 5 seconds, and retry with exponential backoff (roughly 1 min → 5 min → 30
min, three attempts). Internal/private hosts are rejected (SSRF guard). Delivery
outcomes are recorded in `webhook_deliveries`. Events cover create/update/delete for
the main entities plus relationship changes, quality-seal transitions, tag
assign/remove, and bulk import/export completion.

## Reporting, bulk, import/export

- **Reports** — `src/lib/reports.ts` powers `/api/reports/*`: portfolio-health,
  time-distribution, six-r-distribution, obsolescence-risk, capability-coverage.
- **Bulk** — `POST /api/bulk` supports bulk update (default), delete (`?action=delete`),
  and upsert (`?action=upsert`), capped at 100 entities per request.
- **Import** — `POST /api/import` parses CSV (preview or execute mode, batch upserts,
  column whitelist).
- **Export** — `GET /api/export?type=...&format=csv` streams a CSV download.

## Testing

Tests run under **Vitest**:

```bash
npm run test          # run once
npm run test:watch    # watch mode
npm run test:coverage # with coverage
```

V1 has **488 tests across 18 test files**. Before pushing, `npm run check` runs lint,
type-check, format-check, tests, and build together.

## Conventions recap

- Server Components by default; `"use client"` only when needed.
- Use `@/lib/data` for data access — do not inline data in pages.
- Use Rosely colour tokens (`text-rosely-night`, `bg-rosely-cream`, …) — no raw hex.
- Use shadcn/ui primitives from `@/components/ui/`.
- Use `size-N` for square icons and `flex flex-col gap-N` for vertical spacing.
- `params`/`searchParams` in pages are **async** — `await` them (Next.js 16).
- Use `after()` from `next/server` for non-blocking post-response work.
- Use `withRetry()` from `@/lib/neon-retry` for critical database operations.
